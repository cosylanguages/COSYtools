# Native Apps (Android, iOS, Windows/macOS/Linux)

COSYtools ships as a static, 100% client-side web app. This document describes how the
same code is wrapped into native apps without forking the site or introducing a build
step for normal web development.

Two shells are provided under `native/`:

| Shell | Directory | Targets | Tool |
|---|---|---|---|
| Mobile | `native/capacitor` | Android, iOS | [Capacitor](https://capacitorjs.com/) 7 |
| Desktop | `native/electron` | Windows, macOS, Linux | [Electron](https://www.electronjs.org/) + electron-builder |

Both shells load the **same** generated web bundle, `native/www`, so there is a single
source of truth for application code.

---

## 1. The web bundle

`scripts/build-app.js` copies the repository into `native/www`, excluding web-only and
build-only paths (git metadata, CI, `scripts/`, `docs/`, `schemas/`, the native project
itself, Markdown, and `404.html` — whose `<base href="/COSYtools/">` only resolves on
GitHub Pages). It writes a hash manifest to `native/.www-manifest.json`.

```bash
npm run app:build          # build native/www
npm run check:app-bundle   # fail if native/www is stale
```

`native/www` is a build artifact and is not committed.

---

## 2. Mobile shell (Capacitor)

`native/capacitor/capacitor.config.json` points `webDir` at `../www`, so Capacitor copies
the bundle into each platform project. The app id is `io.github.cosylanguages.cosytools`
and the display name is `COSYtools`.

### One-time / after brand changes: icons and splashes

`scripts/generate-app-sources.js` derives the master source images from
`shared/images/cosylanguages.png`:

```bash
npm run app:sources                                  # writes native/capacitor/assets/*.png
cd native/capacitor && npx capacitor-assets generate # writes platform icon/splash sets
```

`@capacitor/assets` produces the full Android density set (including adaptive and
dark-mode variants) and the iOS asset catalogue.

### Adding or refreshing a platform project

Platform projects are generated, not hand-edited. To recreate them:

```bash
cd native/capacitor
npm ci
npx cap add android     # and/or: npx cap add ios
npx cap sync            # copies native/www + plugins into every platform
```

`npx cap sync` is the command to run after any web change; it rebuilds nothing on its own
but copies the current `native/www` into `android/app/src/main/assets/public` and
`ios/App/App/public`.

### Android

Requires JDK 21 and the Android SDK.

```bash
cd native/capacitor/android
./gradlew assembleDebug          # debug APK
./gradlew bundleRelease          # Play Store AAB (needs a signing config)
```

Output: `native/capacitor/android/app/build/outputs/apk/debug/app-debug.apk`.

### iOS

Requires macOS with Xcode and CocoaPods.

```bash
cd native/capacitor
npx cap sync ios
npx cap open ios                 # then archive/upload from Xcode
```

The generated `ios/` project is committed (Capacitor's own `.gitignore` excludes `Pods/`,
`public/`, and generated config). CocoaPods must run on macOS before the first build.

---

## 3. Desktop shell (Electron)

`native/electron/main.js` serves the bundle over a custom `app://` scheme rather than
`file://`, so relative `fetch()` calls (the app's JSON datasets) behave exactly as they do
on the web. It is a thin wrapper: no Node APIs are exposed to the page
(`contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`), external links open
in the system browser, and a single-instance lock prevents duplicate windows.

```bash
cd native/electron
npm ci
npm start                        # run from the source tree (uses ../www)
npm run dist:win                 # Windows NSIS installer
npm run dist:mac                 # macOS DMG
npm run dist:linux               # Linux AppImage
```

`electron-builder` reads its configuration from the `build` field of
`native/electron/package.json` and writes installers to `native/electron/dist`. The app
icon is `native/electron/build/icon.png` (generated by `npm run app:sources`);
electron-builder converts it to `.ico`/`.icns` per platform.

---

## 4. CI

`.github/workflows/native.yml` runs on changes to `native/**`, the app build scripts, or
the site itself:

- **bundle** — builds `native/www`, verifies it is reproducible, and syntax-checks the
  Electron main process.
- **android** — builds a debug APK on JDK 21 + the Android SDK and uploads it as an
  artifact.
- **desktop** — packages on Ubuntu, Windows, and macOS and uploads the installers.

iOS builds require a macOS runner with signing credentials and are intentionally left to
a release workflow rather than the default PR check.

---

## 5. Offline behaviour

The web app already registers a service worker (`sw.js`) on `http(s)` origins, which
covers the Electron shell (`app://` is not `http`, so no service worker runs there) and the
hosted PWA. In Capacitor the bundle is served from the app package itself, so the app is
offline by construction and needs no service worker.

The only network dependency is the optional COSYdata daily feed. When offline it fails
silently and the rest of the app is unaffected.

---

## 6. Adding another COSY app (COSYgames, COSYpractice)

The pattern is deliberately repo-local: each repo gets its own `scripts/build-app.js`,
`native/capacitor`, and `native/electron`, differing only in the app id, display name, and
the set of paths excluded from `native/www`. COSYpractice additionally fetches
`themes.json` from `raw.githubusercontent.com`, so its bundle must either allow that origin
or vendor the file.

---

## 7. Troubleshooting

- **`npx cap sync` copies nothing / stale content** — run `npm run app:build` first;
  Capacitor copies `native/www`, which is not rebuilt automatically.
- **Electron shows a blank window** — confirm `native/www/index.html` exists
  (`npm run app:build`). The shell resolves the bundle relative to `main.js` in packaged
  builds and to `../www` in the source tree.
- **`SUID sandbox helper binary ... not configured correctly` on Linux** — a runner
  detail, not an app defect. Either run on a normal desktop, or
  `chown root:root chrome-sandbox && chmod 4755 chrome-sandbox` for headless CI.
- **Android build fails on Java version** — Capacitor 7 requires JDK 21
  (`sourceCompatibility VERSION_21` in `app/capacitor.build.gradle`).
